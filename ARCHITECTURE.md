# GoTrader AI Lab Architecture

## 1. Overview

GoTrader AI Lab is a local-first React/Vite research workbench for futures-style strategy research. It renders charts, imports and normalizes candle data, runs deterministic ICT/Grinch analysis, runs internal research agents, coordinates a debate and CIO synthesis layer, evaluates research quality, and blocks all broker execution paths.

Current working areas in code include the Vite/React app, the collapsible app shell, dashboard Command Center, canonical candle source manager, imported OHLCV storage, MT5 read-only market-data bridge contract, TradingView MCP read-only bridge, deterministic regime classifier, agent registry, debate orchestration, autonomous research loop, walk-forward testing, readiness/evidence/maturity gates, and local LLM advisory bridge plumbing. Areas still marked planned or partial in code include Tradovate read-only, MT5 execution, Paperclip/OpenClaw/Hermes planning, order-flow depth data, Monte Carlo robustness beyond placeholder reporting, and live broker truth.

Primary instruments in the type system are `ES`, `NQ`, `MES`, and `MNQ` in `src/lib/types.ts`. The project copy and docs repeatedly focus on ES/NQ/YM intraday futures research; YM is represented in source aliases and UI text, but the core `FuturesSymbol` union currently includes ES/NQ/MES/MNQ only.

The core design philosophy is research first, execution never. Market data can be imported, read from MT5 read-only, or read from TradingView MCP, but every bridge and source is labeled read-only and carries authority fields set to `none`.

### 6.2 Debate Protocol

`src/lib/agentDebate/runAgentDebateSession.ts` runs the protocol:

1. `createOpeningStatements` builds statements from selected internal agent opinions and immutable facts.
2. `runDebateRound` creates deterministic challenge/defense messages for each round.
3. `validateDebateMessage` rejects execution, broker, order, readiness override, and live-trading wording.
4. `moderateDebateConsensus` counts aligned agent votes and produces long/short/flat consensus.
5. `runAgentDebateSession` stores the latest 10 sessions under `gotrader_ai_lab_agent_debate_state`.

## 7. Autonomous Research Loop

### 7.1 Loop Stages

`src/lib/autonomousResearch/runAutonomousResearchLoop.ts` implements these stages:

1. `resolving_runtime`
2. `thesis_generation`
3. `backtest`
4. `llm_advisory`
5. `auto_research`
6. `walk_forward`
7. `self_improvement`
8. `readiness_maturity`
9. `audit_communications`
10. `completed`, `paused`, `canceled`, or `failed`

### 7.2 Auto-Apply Eligibility

`src/lib/autonomousResearch/autoApplyResearchCalibration.ts` allows only research calibration fields:

- `confluenceThreshold`
- `confidenceThreshold`
- `sessionFilter`
- `stopModel`
- `targetRMultiple`
- `allowLong`
- `allowShort`
- `ictScoringWeights`
- `agentWeights`
- `confidencePenaltyRules`
- `evidenceQualityPenaltyRules`

Forbidden categories live in `src/lib/autoResearch/configSearchSpace.ts`: broker/live/API/readiness/execution fields are explicitly prohibited.

Required conditions include enabled auto-apply policy, proposal intent `research_calibration_candidate`, proposal status `proposed` or `testing`, `canApprove`, positive material change, no snapshot mismatch, no critical regression, sample size/evidence thresholds, non-failing walk-forward, no regime mismatch, no maturity drop, LLM pass when required, and bounded deltas for thresholds and weights.

### 7.3 Stop Conditions

The loop stops or pauses on user cancel, failure, regime mismatch, evidence quality below 45, repeated walk-forward failures, Paper-Demo Candidate review reached, stable Research Ready state, no improvement for configured iterations, or max iteration count.

### 7.4 State Persistence

Autonomous loop state is stored in `localStorage` under `gotrader_ai_lab_autonomous_research_state`. Safety state uses `gotrader_ai_lab_autonomy_safety_state`. Research cycle state uses `gotrader_ai_lab_research_cycle_state`.

## 9. LLM Integration

### 9.1 Local Bridge Server

`scripts/llm-local-bridge-server.mjs` runs on `127.0.0.1:8787` by default. It exposes `GET /`, `GET /health`, and `POST /llm/run-advisory`. It validates localhost origins, requires advisory-only mode, and writes latest response JSON to `llm/responses/latest-llm-response.json`.

`scripts/gpt55-llm-agent-provider.mjs` calls OpenAI's Responses API with model `gpt-5.5` by default, overrideable with `GOTRADER_LLM_MODEL`. It requires `OPENAI_API_KEY` and validates a strict advisory JSON schema.

### 9.2 Advisory Layer

The `advisory/` folder contains latest request/response artifacts and processed JSON from advisory runs. It is local artifact storage, not source code.

### 9.3 LLM Folder

The `llm/` folder contains `.gitkeep`, latest bridge responses, and error JSON artifacts. It is consumed by local scripts and human debugging.

### 9.4 Prompt Architecture

Prompts are defined in `src/lib/llm/llmPromptTemplates.ts`. `REQUIRED_LLM_AGENT_IDS` contains 14 advisory reviewers, and the system prompt forbids execution, broker control, readiness override, API keys, and trade placement.

`scripts/start-mt5-readonly-bridge.mjs` starts a GoTrader safe wrapper on `127.0.0.1:7341`. It can call a configured upstream at `MT5_READONLY_UPSTREAM_BASE_URL`, expected locally around `http://127.0.0.1:8000`. The exact broker/feed is not hard-coded in the repo; the code treats symbols such as `USTECH` as MT5 broker CFD/proxy data for a requested GoTrader symbol such as `MNQ`.

### 11.2 Available Data

The safe wrapper exposes only `GET /health`, `/status`, `/symbols`, `/symbol-info`, `/quote`, `/candles`, `/snapshot`, and `/tool-policy`. It tries safe upstream paths for health/status, symbols, symbol info, quote/price/tick, and candles/rates/OHLCV. It maps GoTrader timeframes to MT5 timeframes such as `5m -> M5`.

### 11.3 Safety Constraints

Safety is enforced in `scripts/mt5-readonly-tool-policy.mjs` and `scripts/start-mt5-readonly-bridge.mjs`. The policy defines allowed read-only tool families and blocked mutation tokens. The bridge returns `403` for blocked mutation paths and `405` for non-GET methods on read endpoints. Every normalized quote/candle/snapshot response includes:

```ts
executionAuthority: "none"
brokerAuthority: "none"
readinessOverrideAuthority: "none"
```

### 11.4 Safety Test Coverage

`scripts/test-mt5-readonly-safety.mjs` verifies that dangerous tool names and paths containing account/order/position/deal/buy/sell/close/modify/cancel tokens are blocked. If the bridge is running, it also probes forbidden routes for 403/405 behavior and verifies that `POST /quote` is not allowed.

## 12. Regime Classifier

### 12.1 Algorithm

`src/lib/regime/compositeRegimeClassifier.ts` implements a deterministic composite classifier. It computes ATR ratio, realized volatility percentile, directional efficiency, VWAP distance/slope/cross count, opening range expansion, range compression/chop, macro/intermarket context when available, and event risk when available.

### 12.2 Regime Labels

Labels from `src/lib/regime/regimeTypes.ts`:

- `trend_bull`
- `trend_bear`
- `range_low_vol`
- `range_high_vol`
- `event_high_vol`
- `risk_off_crisis`
- `insufficient_data`

It also returns instantaneous/stable labels, transition state, confidence, data quality, supporting factors, conflict score, scores, recommended behavior, and missing inputs.

### 12.3 Integration

`src/lib/agents/runAgents.ts` calls the classifier before running agents and passes `regimeClassification` into `InternalAgentRunContext`. `src/lib/regime/regimeAgentWeights.ts` adjusts weights by regime. The autonomous loop reads regime status through the runtime snapshot and can pause on regime mismatch.

### 12.4 Test Coverage

`scripts/test-regime-classifier.mjs` verifies insufficient data, trend bull, trend bear, range low vol, range high vol, event high vol, hysteresis, and JSONL history logging through the script-side history service.

## 14. Safety Architecture

### 14.1 Hard Locks

Hard execution locks appear in multiple layers:

- MT5 wrapper blocks mutation paths and non-GET calls in `scripts/start-mt5-readonly-bridge.mjs`.
- MT5 policy blocks account/order/position/deal/buy/sell/close/modify/cancel tokens in `scripts/mt5-readonly-tool-policy.mjs`.
- Broker route policy in `src/lib/brokers/brokerAuthorityPolicy.ts` creates blocked research risk decisions and sets execution intent authority to none.
- `src/lib/brokers/brokerRouter.ts` returns broker routes with `executionAuthority: "none"` and `brokerAuthority: "none"`.
- `src/lib/llm/llmPromptTemplates.ts` forbids execution, broker control, readiness override, and API keys in advisory prompts.
- `tests/smoke/routes.spec.ts` and `scripts/smoke-routes.mjs` reject visible order/live controls such as Place Order, Buy Market, Sell Market, Enable Live Trading, and Connect Live Broker.

### 14.2 Go-Trader Handoff Gate

`src/lib/integration/createGoTraderHandoff.ts` creates a simulation handoff with broker connection, live trading, external API, and order execution all false. `src/lib/autonomousResearch/runAutonomousResearchLoop.ts` only marks review eligibility when readiness, maturity, evidence, walk-forward, and runbook checks pass. Broker execution remains disabled.

### 14.3 Research-Only Boundary

The research-only boundary is enforced by authority objects (`executionAuthority`, `brokerAuthority`, `readinessOverrideAuthority`), blocked MT5 mutation routes, broker route policies, prompt guardrails, and smoke-test assertions for unsafe UI labels.

### 14.4 Safety Gaps

`src/lib/integration/validateGoTraderHandoff.ts` validates handoff shape but does not fully verify every safety field created by `createGoTraderHandoff.ts`. The creator sets the safety fields to false, but the validator is not a complete independent safety validator. This should be treated as a safety gap.

12. `@vitejs/plugin-react` is listed in runtime dependencies, although it is a build plugin. Recommended fix: consider moving it to `devDependencies`.
