## Cohesion Audit Summary

Overall cohesion is good at the read-model and UI-warning level. The major systems now share the canonical `ResearchRuntimeSnapshot`, and Grinch Phase 1 through Phase 4 state is available to the runtime, dashboard, ICT Lab, LLM context, Auto Research, walk-forward, evidence quality, and maturity/readiness views.

The largest weakness is operational: local file import is browser-local IndexedDB state. If the browser storage has no imported dataset, the app cannot reconstruct it from the local XLSX file without a manual browser upload or a dedicated local import helper. That makes automated imported-data validation fragile.

## Passing Integrations

- Runtime snapshot includes Grinch Phase 1, Reversal, Consolidation, SMT, compact SMT summary, active Grinch profile, and Grinch strategy score.
- Dashboard Mission Control displays data-source status, Grinch model score, false-positive risk, SMT unavailable state, evidence, maturity, readiness, walk-forward, and safety locks.
- ICT Lab independently computes and displays Grinch score breakdown, profile validity, rule blocks, missing evidence, Phase 1, Reversal, Consolidation, SMT, and chart overlays.
- Auto Research scoring includes `grinchModelSupport`, `grinchModelScore`, `grinchFalsePositiveRisk`, and Grinch candidate families.
- Auto Research reports ICT foundation plus Grinch refinement layer contribution, including Grinch-qualified and Grinch-blocked ICT setups.
- Walk-forward stores Grinch metrics per window, including profile detected, profile validity, Grinch score, time alignment, PD alignment, opening-price alignment, SMT state, and false-positive risk.
- LLM context includes compact Phase 1, Reversal, Consolidation, and SMT summaries, with prompt instructions that Grinch is advisory context only.
- Evidence Quality marks SMT unavailable when correlated NQ/ES/YM evidence is missing and does not treat unavailable SMT as confirmation.
- Readiness still uses Grinch as supporting evidence only; it does not bypass trade count, average R, drawdown, walk-forward, evidence, maturity, LLM, or runbook gates.
- Walk-forward refuses imported-data validation when active source is mock.
- Mock data is clearly labeled as not valid for imported MNQ comparison.
- Broker, go-trader, Tradovate, live trading, order execution, and readiness override remain locked.

## Broken or Weak Integrations

- Automated import is not currently possible through the Codex in-app browser because local file uploads are unsupported.
- The app has no safe local file import bridge for test automation. Without an existing IndexedDB import, an automated imported MNQ validation run cannot be reproduced.
- Runtime proposal mismatch diagnostics were too literal before this audit: proposal snapshots from an Auto Research sub-cycle were flagged as different from the parent dashboard cycle even when the parent cycle created that proposal.
- SMT remains unavailable with single-instrument MNQ data. That is correct behavior, but it means Grinch Phase 4 cannot contribute real intermarket confirmation until ES/YM or provider-neutral correlated data are added.
- Current stored walk-forward evidence is insufficient and should not be used to promote any proposal.
- Current stored proposal/research values are mock-context only and should not be used for imported MNQ conclusions.

## Stale or Duplicated Metrics

- Canonical performance metrics are present through the runtime snapshot.
- Proposal metrics use canonical proposal snapshots.
- Dashboard and Self-Improvement can still show different sources by design, but source labels are visible.
- The fixed runtime warning reduces false stale-proposal noise when the proposal source is an Auto Research sub-cycle linked to the latest dashboard cycle.
- No evidence was found that chart overlays feed back into calculation state. The chart layer appears display-only.

## Recommended Fixes in Priority Order

1. Add a safe local MNQ import helper for development/testing that parses the local XLSX server-side and seeds the app through a local-only endpoint or controlled import/export path. It must not expose API keys or broker authority.
2. Add a Market Data verification action that confirms expected MNQ metadata: symbol MNQ, contract 06-26, 1m source, about 40,013 raw candles.
3. Add a Grinch validation report button that only enables when imported data is active and Standard projects about 2,000 raw -> about 400 processed 5m candles.
4. Add ES and YM imported-dataset slots or a provider-neutral correlated-data adapter so SMT can move from unavailable to real confirmation.
5. Add an automated route/import smoke harness outside the in-app browser file-upload limitation.
6. Add a compact dashboard flag for "latest Grinch result is imported-data valid" versus "mock/demo only."
7. Run the imported Standard Grinch test once MNQ import is active, then measure layer contribution against the earlier 77-trade / 9% win-rate ICT foundation result.
