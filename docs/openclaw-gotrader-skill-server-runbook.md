# OpenClaw GoTrader Skill Server Runbook

This runbook starts the phone-side **GoTrader Research Advisor** skill server in Termux/Ubuntu on Android. The existing phone bridge listens on `0.0.0.0:8797` for desktop GoTrader. This skill server listens only on `127.0.0.1:8798` so the phone bridge can forward compact GoTrader advisory packets to it through `OPENCLAW_AGENT_ENDPOINT`.

The skill server is advisory-only. It does not call MT5, brokers, accounts, orders, positions, live trading controls, readiness override paths, or auto-apply paths.

## Files

Source file in GoTrader:

```text
scripts/openclaw-gotrader-advisory-skill-server.mjs
```

Copy this file to the phone, for example:

```text
~/openclaw-gotrader-advisory-skill-server.mjs
```

Also keep a copy of the outer bridge script on the phone:

```text
~/openclaw-phone-advisory-bridge.mjs
```

## Install Node In Termux

If Node is not installed:

```bash
pkg update
pkg install nodejs
node --version
```

If using Ubuntu inside Termux:

```bash
sudo apt update
sudo apt install nodejs
node --version
```

## Phone Terminal 1: Start The Skill Server

Run:

```bash
export OPENCLAW_GOTRADER_SKILL_HOST=127.0.0.1
export OPENCLAW_GOTRADER_SKILL_PORT=8798
node openclaw-gotrader-advisory-skill-server.mjs
```

Default listener:

```text
http://127.0.0.1:8798
```

Routes:

```http
GET /health
POST /gotrader/advisory-skill
OPTIONS /*
```

Health check on the phone:

```bash
curl http://127.0.0.1:8798/health
```

Expected:

```json
{
  "provider": "openclaw_gotrader_research_advisor",
  "skillStatus": "running",
  "host": "127.0.0.1",
  "port": 8798,
  "route": "/gotrader/advisory-skill",
  "authority": {
    "executionAuthority": "none",
    "brokerAuthority": "none",
    "readinessOverrideAuthority": "none"
  }
}
```

## Phone Terminal 2: Start The Public Phone Bridge

Run the bridge with the local skill endpoint configured:

```bash
export OPENCLAW_AGENT_ENDPOINT="http://127.0.0.1:8798/gotrader/advisory-skill"
export OPENCLAW_AGENT_TIMEOUT_MS=15000
export OPENCLAW_PHONE_BRIDGE_HOST=0.0.0.0
export OPENCLAW_PHONE_BRIDGE_PORT=8797
node openclaw-phone-advisory-bridge.mjs
```

Bridge health check on the phone:

```bash
curl http://127.0.0.1:8797/health
```

Expected bridge fields:

```json
{
  "provider": "openclaw_phone",
  "bridgeStatus": "running",
  "advisoryStatus": "connected",
  "openClawAgentEndpointConfigured": true,
  "authority": {
    "executionAuthority": "none",
    "brokerAuthority": "none",
    "readinessOverrideAuthority": "none"
  }
}
```

If `openClawAgentEndpointConfigured` is `false`, the bridge is still in safe stub mode and will not call the skill server.

```powershell

```

This starts the skill server on a temporary local port and verifies:

- `/health` returns `openclaw_gotrader_research_advisor`
- `POST /gotrader/advisory-skill` returns `OpenClawAdvisoryResponse`
- response mentions the MT5 USTECH / MNQ CFD-proxy source context

You can also run the server locally:

```powershell

```

## Skill Response Behavior

The skill server derives its response from packet fields:

- source provider
- requested symbol
- broker symbol
- candle count
- regime label, confidence, data quality, and transition state
- ICT thesis
- Grinch profile and blocker
- readiness
- evidence score
- maturity score
- walk-forward verdict
- top blockers
- user question

If the source is MT5 `USTECH` for requested `MNQ`, it explicitly labels the source as CFD/proxy data and not CME MNQ futures truth.

If Paper-Demo Candidate gates are not satisfied, the skill keeps the distinction clear: Research Ready means the cycle can be reviewed; Paper-Demo Candidate requires GoTrader validation gates.

## Safety Boundary

The skill server rejects unsafe request fields such as:

- `placeOrder`
- `buyMarket`
- `sellMarket`
- `closePosition`
- `accountMutation`
- `positionMutation`
- `orderRoute`
- `mt5Credentials`

The skill server refuses order/live/buy/sell prompts inside JSON and returns `execution_request_refused`.

The skill server does not:

- call MT5
- call broker APIs
- place orders
- mutate accounts, orders, or positions
- approve readiness
- auto-apply proposals
- expose secrets
- require raw candle arrays

Every response forces:

```json
{
  "executionAuthority": "none",
  "brokerAuthority": "none",
  "readinessOverrideAuthority": "none"
}
```

The outer phone bridge remains the public LAN boundary. The skill server should stay bound to `127.0.0.1` unless there is a deliberate reason to expose it.
